# Decomp oracle (development only)

`rustario64-oracle` compiles byte-identical CC0 sources from
[n64decomp/sm64 at 9921382a68bb0c865e5e45eb594d9c64db59b1af](https://github.com/n64decomp/sm64/tree/9921382a68bb0c865e5e45eb594d9c64db59b1af)
natively, so tests can compare the Rust collision, math, Mario step, input and
action ports, the camera's components and complete frames of Mario with the
original area camera, Mario's blob-shadow vertices and animation offsets, and
the object system (pool, lists, behavior scripts, object collision, yellow
coins, coin formations, sparkles and coin collection, object animations,
Bob-ombs with their explosions, loot coins, respawners and sound spawners,
Mario's damage and grabbable interactions, and holding: his hold, pick-up and
throw actions with the render pass's hand position), Mario's object node in the
render pass through the original traversal, and the enemy movement
component with the original code
bit for bit.

**Boundary.** This crate is a test/comparison tool. Nothing in the game runtime
or renderer depends on it, and it is never shipped. The C keeps global state, so
all access goes through one process-wide lock. It is compiled with `-fwrapv`
(MIPS integer arithmetic wraps) and `-ffp-contract=off` (no fused multiply-add),
giving native IEEE single-precision results. Agreement with N64 execution
still needs original-execution traces.
Float-to-integer casts of values outside the s32 range are outside coverage.

**Replacement plan.** Native compilation of the decomp is a practical oracle,
not original-hardware evidence. Once per-tick traces from original execution
cover these components, those traces become the authority and this harness can
be retired or kept only as a fast regression check.

The sources compile with the original struct layouts from the vendored
`include/types.h` and friends, `AVOID_UB` (standard-compliant table access and
the decomp's defined values for missing returns) and `NO_SEGMENTED_MEMORY`
(host pointers, so segment conversions are identities). Implicit function
declarations are build errors: without a prototype C passes `f32` arguments as
`double` and reads an `int` result, which silently corrupted results before the
missing includes were found (`vec3f_set` in `geo_obj_init_spawninfo`, `absf` in
`update_mario_platform`). Until session 22 the build passed `-w`
(`cc::Build::warnings(false)`), which with GCC 13 also silenced these
`-Werror` diagnostics; the flag is gone, the guard is active, and the two
excerpts that then failed (`bhv_init_room` in behavior_script.c and
`bhv_spawn_star_no_level_exit` in interaction.c, both with integer arguments)
include the header that declares them.

### Boundaries in `c/runtime_glue.c`

- **Recorded, in call order:** sounds and audio state changes (`play_sound`,
  `stop_sound`, `set_sound_moving_speed`, background-noise and cap-music calls),
  Mario's camera requests (`set_camera_mode`, `set_camera_shake_from_hit`;
  with the camera linked they also run the original camera.c functions, which
  `camera_unit.c` compiles under `oracle_camera_native_*` names), warps
  (`level_trigger_warp`, which returns the "no transition" 0 because no level
  runtime runs), `load_level_init_text`, wind particles, and the cutscene and
  submerged action groups, which are not compiled yet: their dispatchers record
  the action and return FALSE. Recorded calls never change compared state.
- **Explicit inputs:** save flags, the saved cap position and the total star
  count. Without the linked camera, the camera mode, yaw and other world
  fields are set by the harness.
- **Camera's outside calls:** `get_dialog_id` returns `DIALOG_NONE` (no
  dialog system runs), `set_hud_camera_status` stores the HUD icon state for
  the snapshot, and `alloc_only_pool_alloc` keeps the original's 4-byte
  rounding over one authored pool sized for the area's `struct Camera`.
- **Object system:** `gCurrAreaIndex` and `gLoadedGraphNodes` are set by the
  harness; `mem_pool_init` returns NULL (memory.c's object pool serves only
  chain chomps and wigglers); `stop_sounds_from_source` has no simulated
  state; the 100-coin star spawn (`bhv_spawn_star_no_level_exit`) is
  recorded as an unsupported event, as the Rust port records it. debug.c's
  boot-time natives (profiler clock, object-info page, debug spawning) do
  nothing, as they do with the debug page disabled. `virtual_to_segmented` is
  the identity (host pointers are their own segmented form under
  `NO_SEGMENTED_MEMORY`, so `cur_obj_has_behavior` compares like the original).
- **Explosions' camera shake:** `set_environmental_camera_shake` is recorded
  as event 14 and, with the camera linked, runs the original camera.c function
  at the call (the Rust frame applies it after the object update; see
  docs/DECISIONS.md, session 22).
- **Display-list arena:** obj_orient_graph allocates its terrain matrix with
  `alloc_display_list`; `oracle_frame_alloc_display_list` serves Mat4 blocks
  from an arena reset at the start of each frame (pool exhaustion is not
  modelled). The snapshot reads a throw matrix's 16 words from it.
- **Fixed-point matrices:** `guMtxF2L` (libultra, called by math_util.c's
  `mtxf_to_mtx`) is an authored implementation of its documented 16.16
  layout; the level-of-detail node reads the integer half of a matrix's z
  translation from it. The SDK source is not vendored.
- **Mario's scaler counter:** geo_mario_hand_foot_scaler keeps a
  function-local counter from boot. Each level entry sets it to a fresh
  boot's value at area update 0 by calling the verbatim function once
  (`oracle_render_prime_scaler`) and restores what that call touched, because
  the oracle runs many entries in one process.
- **Stand-in scripts:** `bhvObjectWaterWave`, `bhvObjectBubble` and
  `bhvBobombExplosionBubble` exist only as distinct addresses; the Rust side
  stops before spawning water particles, so the native frames never run them.
- **Aborting:** the thrown/dropped vertical movement `cur_obj_move_y`, platform displacement by objects, water droplets,
  every interaction handler except `interact_coin`, `interact_damage` and
  `interact_grabbable` (verbatim), and the PSS timer. Nothing the compared
  runs reach calls them (the Rust side stops at grabs first); reaching one
  fails the test loudly.
- **Animation DMA:** `load_patchable_table` keeps the original contract and
  checks with `dma_read` replaced by a copy from a host-layout table that the
  harness builds from the decoded ROM table (native `struct Animation` headers
  with the same header-relative array offsets the ROM uses).
- Debug text functions are no-ops (`gShowDebugText` is FALSE).

### The tick harness (`c/tick.c`)

`oracle_tick_begin` enters a level the way `init_level` does without a warp
destination (the branch demos and the level select take) from a fresh boot:
`init_mario_from_save_file`, `clear_objects`, the area's macro objects and
spawn infos, Mario's object spawned from `gMarioSpawnInfo`, `init_mario`, then
`set_mario_action(ACT_IDLE)`. `oracle_tick_run` runs one frame in the
original order: `read_controller_inputs` for controller 1, the camera yaw the
camera computed last frame (a recorded input), `gAreaUpdateCounter++`, the
verbatim `update_objects` (`clear_dynamic_surfaces`, the terrain lists,
Mario's platform displacement, `detect_object_collisions`, the remaining
lists of `sObjectListUpdateOrder`, with `cur_obj_update` interpreting each
object's script, then unloading of deactivated objects and
`update_mario_platform`), the render pass for Mario's node (with the camera linked and a Mario model
given, the verbatim geo_process_object and his model's traversal in
c/mario_render_unit.c: his animation, his callbacks' body-state writes, levels
of detail and the held object's node, which writes the HOLP and processes the
held object's model; otherwise its `geo_process_object` condition and
`geo_set_animation_globals`) and the authoritative writes for the other
objects (their animation frame advance, throw-matrix placement and switch
cases), and `gGlobalTimer++`. The per-frame display-list arena is
reset where the game selects a new display-list pool. State persists across frames; the Rust side runs
independently and nothing is copied between them after the level entry.

With `cameraLinked` the area's camera is the original one instead of explicit
inputs: `oracle_camera_create` starts the camera globals from a fresh boot's
values, seeds gRandomSeed16, sets the act, runs `select_mario_cam_mode` and the
area's GEO_CAMERA node's create callback (`geo_camera_main`, which runs
`create_camera`); `reset_camera` follows `init_mario`; each frame runs
`update_camera` after the objects and, in the render pass, the area's
perspective node (`geo_camera_fov`) and camera node (`geo_camera_main`, which
runs `update_graph_node_camera`) before Mario's object node. Mario reads the
yaw the camera produced the previous frame (`gCurrentArea->camera->yaw`), so
nothing is supplied. `oracle_camera_create` refuses a level whose original
`sCameraTriggers` entry is not NULL (the `level_defines.h` table is checked by
name), because no trigger table is vendored; BOB has none.

Objects run through the original object system. The level entry runs the
verbatim `clear_objects`, then `spawn_macro_objects` over the area's macro
entries whose behavior the port runs (with the ROM's preset rows for them),
then `spawn_objects_from_info` over the matching spawn infos and Mario's. Each
frame runs the verbatim `update_objects`: `cur_obj_update` interprets the
verbatim scripts (`c/excerpts/behavior_data.c`), whose natives are the verbatim
coin, Bob-omb, explosion, moving-coin, respawner and sound-spawner behaviors,
obj_behaviors.c's helpers and the object helpers; object collision,
`interact_coin`, `interact_damage` and `interact_grabbable` run from the
vendored and excerpted files. The Bob-omb's animation table is a host copy
(`c/object_anims_unit.c`) built from the same decode the Rust side uses, and
`oAnimations`/`curAnim` compare by their segmented addresses. A placement whose script the port does
not run yet is skipped on both sides (the same filtered set; the Rust side
lists them in `AreaObjects::skipped`). The render pass's authoritative writes
for other objects (`oAnimState` through `geo_switch_anim_state` for objects
`obj_is_in_view` accepts) run in `c/object_render_unit.c` from the current
camera node. Behavior pointers compare by their segmented address in segment
0x13, so `behavior`, `curBhvCommand` and the behavior stack are the same words
the ROM's scripts have.

Original code runs unmodified for every function it calls. Authored and
mirrored in Rust: bhv_mario_update without `spawn_particle`, the render
traversal around the verbatim view and switch functions, and the entry
sequence. Not run: particle spawning (the flags stay in
`oMarioParticleFlags`), the HUD, warps, and the render pass's
presentation-only writes (display lists, torso and head angles, the
hand-scale counter). `oracle_tick_snapshot` returns every compared
value as a named 32-bit word (MarioState, Mario's object including all 0x50
raw words, body and camera-status state, world globals, interaction statics,
floor-align matrices, the loaded animation, controller 1 and the frame's
boundary events; every object list in order, the free list, every other
object's graph node (including its animation state and throw-matrix words),
raw words (pointer fields as segmented addresses), behavior stack, hitboxes,
collisions and respawn record, the time-stop state and the compared placements' respawn
bits); `src/tick_trace.rs` produces the same names from Rust state.
With the camera linked the snapshot adds `oracle_camera_snapshot`, the
camera.c state the modelled path can read or change: the `struct Camera`,
every field of gLakituState, the mode transition and mode info, Mario's
camera geometry, the FOV state, the camera flags and movement globals, the
handheld shake state, C-Up's stored camera, the cutscene and credits values
the dispatcher reads, the RNG seed, the HUD camera status and the graph
node's position, focus, roll and field of view (`src/camera_trace.rs` captures the
same names from `simulation::game`).

`--test objects` compares complete frames with objects: Mario, the original
camera and every object word. The CI test enters an authored field with 18
macro entries (yellow coins on the floor, high above it and over a void, and
every coin formation type: horizontal and vertical lines, horizontal and
vertical rings, the arrow, flying variants, and a far formation with
preset respawn bits) and runs six starts for 900 frames each with seeded
movement, jumps, dives and camera buttons. The ignored test starts Mario on
BOB's act-1 ground formations with the ROM's scripts, presets and coin models
at four yaws for 600 frames each. Both assert coverage (coins collected,
formations unloading and respawning, both sparkle behaviors, shadowless
coins).

`--test bobombs` compares the same words with Bob-ombs, including holding:
the held state, Mario's holding actions and the HOLP the render pass
writes through his model. The CI tests enter an
authored field (a ramp, a block, a lava tile, a pit over a death plane) with
twelve Bob-ombs (one stationary) and an authored Bob-omb-shaped animation set
(invented values): ten seeded runs of 900 frames with movement, jumps, dives
and attacks let Bob-ombs chase Mario, light fuses, explode, burn, fall, drop
loot and respawn, and five scripted encounters place Mario beside the
stationary Bob-omb to jump-kick it (four), then punch it up and carry,
throw, drop, air-throw, jump and land with, walk and turn with, re-grab and
hold it until its fuse runs out (seven), and dive into it from a run (one);
the authored set uses an authored Mario-shaped model (mario_geo's hierarchy
and callbacks with invented lengths). A third CI test carries a Bob-omb from
a plateau down a slippery slope into a held butt slide. The ignored test adds
the same holding scripts beside BOB's stationary Bob-omb with the ROM's Mario
model. The ignored test starts
Mario beside each of BOB's twelve act-1 Bob-ombs at four yaws for 600 frames
with the ROM's scripts, animations and models. All assert coverage (fuses,
chases, explosions, environmental shakes, deaths, respawns, loot, knockbacks,
launches, held frames, throws, drops, HOLP updates). A run that reaches a
path the port does not run stops; the frames before it are compared and the
stop is reported (none does now). `tick_trace --camera`
and reference-camera replays enter BOB with
its act-1 objects as the viewer does; the Mario-only trace (no camera) keeps
Mario as the only object.

`tick_trace --camera` runs a built-in 60-second program with the camera's
buttons (C-Left/Right, C-Down, C-Up and its exit, R) from BOB's script start
with the original camera linked on both sides and compares every word of
Mario and the camera each frame. `tick_trace --inputs` replays a run recorded
by the viewer (`rustario64-viewer view ROM --mario --record private/runs`)
from BOB's script start in the native decomp and compares every frame;
recordings made with the reference camera (input log schema 2,
`"camera": "reference"`) replay with the camera linked and first check that
each recorded yaw is the one the replay's Mario reads. A path the port does
not support ends the comparison at the previous frame, as it ends play. The
CI test `played_sessions_with_the_camera_replay_exactly_in_the_decomp` does
the same for `play::Session` runs on the authored playground.

The authored tests run on independently authored collision streams, terrain,
tables and animation data (CI-safe); the ignored tests use BOB's real
collision, the real trig tables and Mario's real animations from the owner's
ROM. Coverage counts are in [docs/FIDELITY.md](../docs/FIDELITY.md).

## Camera component oracle

`c/camera_unit.c` compiles `c/excerpts/camera.c` with original headers and
authored prototypes for helpers absent from camera.h (`c/shim/camera_boundary.h`).
`src/camera.rs` holds the existing global lock, loads authored/owner terrain and
trig tables, and reports exact native words. It runs the persistent Lakitu and
transition stage independently of mode dispatch; the complete Mario tick oracle
is unchanged.

original area camera linked, on the authored playground (scripted programs
for every BOB camera mode and C button path, plus seeded fuzz), at 15 to 144 Hz
presentation, through played `play::Session` runs, and (ignored, owner ROM) on

transition state, speeds, deterministic shakes, render position/focus, and
collision flags. The adapter copies authored goals and Mario positions into C,
never the Rust result after a tick. `lakitu_end_frame` performs the outer
`update_camera` assignment of lastFrameAction separately. The 94-word layout is
generated on both sides from field mappings only; `tools/lakitu_layout.py
--check` verifies it and native reset checks the word count.

`set_camera_shake_from_hit` and `set_camera_mode` are renamed during camera
excerpt preprocessing to keep Mario's existing event-recording boundary; the
glue forwards to them while the camera is linked. `random_u16` and
`random_float` are the original `behavior_script.c` functions over the shared
gRandomSeed16 (`c/rng_unit.c`), so the handheld shake and the shock shake
compare exactly. Modes, transitions and cutscenes that BOB never reaches are
authored aborting stubs (`mode_behind_mario_camera`, water surface, cannon,
8-direction, outward radial, parallel tracking, slide, fixed, spiral stairs,
`play_cutscene`, `determine_dance_cutscene`, `set_fixed_cam_axis_sa_lobby`),
and `sModeTransitions` is an authored table pointing at the compiled and
stub functions. Cutscene, spline and trigger tables are not copied into the
repository: `sCameraTriggers` is all NULL and the frame adapter checks the
level's original entry by name.

`--test radial` compares obstruction helpers, eight-probe wall scans, radial
rotation, outward offsets and zoom. Native globals remain independent across
rotation, zoom, radial goal construction and Lakitu updates. The authored stage
adapter deliberately omits full mode input, set_camera_height, pan and dispatch;
it is not a replacement for mode_radial_camera. Vertex tests transport only
vertices/type, forcing the reference to recompute its own integer normal.
The owner-ROM case is `bob_radial_and_obstruction_stages_match_with_rom_tables`.

### Shadow comparisons

`cargo test --locked --release -p rustario64-oracle --test shadow` checks
38,475 authored floor/slope/edge/water/ice/animation cases and 7,680 root-offset
cases against the verbatim original routines. The ignored owner-ROM check adds
8,400 BOB grid shadows and 360 played frames, and compares complete Mario and
camera state with a session that does not draw shadows. `RUSTARIO64_ROM=ROM`
and `-- --include-ignored` enable it. Integer vertex/UV coordinates, opacity and
layer compare exactly; animation-origin floats compare by their bits. No
original-hardware or pixel-perfect N64 renderer claim is made.

cargo test --locked --release -p rustario64-oracle --test object_motion
RUSTARIO64_ROM=/path/to/sm64.z64 cargo test --locked --release -p rustario64-oracle --test object_motion -- --include-ignored --nocapture

standard movement family are not enabled. See docs/FIDELITY.md for coverage and
limits; this is a component comparison, not a complete actor/frame or N64 claim.
