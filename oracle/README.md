# Decomp oracle (development only)

`rustario64-oracle` compiles byte-identical CC0 sources from
[n64decomp/sm64 at 9921382a68bb0c865e5e45eb594d9c64db59b1af](https://github.com/n64decomp/sm64/tree/9921382a68bb0c865e5e45eb594d9c64db59b1af)
natively, so tests can compare the Rust collision, math, Mario step, input and
action ports and camera components with the original code bit for bit.

**Boundary.** This crate is a test/comparison tool. Nothing in the game runtime
or renderer depends on it, and it is never shipped. The C keeps global state, so
all access goes through one process-wide lock. It is compiled with `-fwrapv`
(MIPS integer arithmetic wraps) and `-ffp-contract=off` (no fused multiply-add),
giving native IEEE single-precision results. Agreement with N64 execution
still needs original-execution traces.
Float-to-integer casts of values outside the s32 range are outside coverage.

**Replacement plan.** Native compilation of the decomp is a practical oracle,
not original-hardware evidence. Once per-tick traces from original execution
cover these components, those traces become the authority and this harness can
be retired or kept only as a fast regression check.

## Layout

| Path | Content | Terms |
| --- | --- | --- |
| `c/decomp/` | Whole files copied unmodified from the pinned decomp (table below): the collision loader and queries, math utilities, `mario.c`, `mario_step.c`, the stationary, moving, airborne, object and automatic action files, and every game header they include | CC0, `c/decomp/LICENSE-CC0.txt` |
| `c/excerpts/` | Verbatim items from further decomp files, generated by `tools/extract_excerpts.py` from a clean pinned checkout (table below); only the include lines at the top are authored | CC0 items, MIT include lines |

| `c/runtime_glue.c`, `c/runtime.h` | Authored definitions of the globals and external functions the vendored code references: recorded boundaries, explicit inputs, aborting stubs, and a host stand-in for the animation DMA | MIT |

The sources compile with the original struct layouts from the vendored
`include/types.h` and friends, `AVOID_UB` (standard-compliant table access and
the decomp's defined values for missing returns) and `NO_SEGMENTED_MEMORY`
(host pointers, so segment conversions are identities). Implicit function
declarations are build errors: without a prototype C passes `f32` arguments as
`double` and reads an `int` result, which silently corrupted results before the
missing includes were found (`vec3f_set` in `geo_obj_init_spawninfo`, `absf` in
`update_mario_platform`).

### Boundaries in `c/runtime_glue.c`

- **Recorded, in call order:** sounds and audio state changes (`play_sound`,
  `stop_sound`, `set_sound_moving_speed`, background-noise and cap-music calls),
  camera requests (`set_camera_mode`, `set_camera_shake_from_hit`), warps
  (`level_trigger_warp`, which returns the "no transition" 0 because no level
  runtime runs), `load_level_init_text`, wind particles, and the cutscene and
  submerged action groups, which are not compiled yet: their dispatchers record
  the action and return FALSE. Recorded calls never change compared state.
- **Explicit inputs:** save flags, the saved cap position and the total star
  count. The camera mode, yaw and other world fields are set by the harness.
- **Aborting:** anything that needs objects (spawning, holding, interaction
  handlers, behavior address conversions) or the PSS timer. With no objects
  loaded these are unreachable; reaching one fails the test loudly.
- **Animation DMA:** `load_patchable_table` keeps the original contract and
  checks with `dma_read` replaced by a copy from a host-layout table that the
  harness builds from the decoded ROM table (native `struct Animation` headers
  with the same header-relative array offsets the ROM uses).
- Debug text functions are no-ops (`gShowDebugText` is FALSE).

### The tick harness (`c/tick.c`)

`oracle_tick_begin` enters a level the way `init_level` does without a warp
destination (the branch demos and the level select take) from a fresh boot:
`init_mario_from_save_file`, Mario's object spawned from `gMarioSpawnInfo`,
`init_mario`, then `set_mario_action(ACT_IDLE)`. `oracle_tick_run` runs one
frame in the original order: `read_controller_inputs` for controller 1, the
camera yaw the camera computed last frame (a recorded input),
`gAreaUpdateCounter++`, `update_objects` with Mario as the only object
(`clear_dynamic_surfaces`, `clear_object_collision`, `cur_obj_update` running
bhvMario's script and `bhv_mario_update`, `update_mario_platform`), the render
pass's `geo_process_object` condition and `geo_set_animation_globals`, and
`gGlobalTimer++`. State persists across frames; the Rust side runs
independently and nothing is copied between them after the level entry.

Original code runs unmodified for every function it calls. Authored and
mirrored in Rust: the object-pool slot reset and `allocate_object` field values
for Mario's object, bhvMario's commands before `BEGIN_LOOP`, the render
condition, and the entry sequence. Not run: particle spawning (the flags stay in
`oMarioParticleFlags`), the debug-page natives, the camera update, the HUD,
warps, and the render pass's presentation-only writes (matrices, torso and head
angles, the hand-scale counter). `oracle_tick_snapshot` returns every compared
value as a named 32-bit word (MarioState, Mario's object including all 0x50
raw words, body and camera-status state, world globals, interaction statics,
floor-align matrices, the loaded animation, controller 1 and the frame's
boundary events); `src/tick_trace.rs` produces the same names from Rust state.

## Tests

```sh
cargo test --locked -p rustario64-oracle
RUSTARIO64_ROM=/path/to/sm64.z64 cargo test --locked --release -p rustario64-oracle -- --ignored --nocapture
cargo run --locked --release -p rustario64-oracle --example input_trace -- /path/to/sm64.z64 private/input-traces
cargo run --locked --release -p rustario64-oracle --example tick_trace -- /path/to/sm64.z64 private/tick-traces
cargo run --locked --release -p rustario64-oracle --example tick_trace -- /path/to/sm64.z64 private/replay-1 --inputs private/runs/run-001.inputs.json
```

`tick_trace --inputs` replays a run recorded by the viewer
(`rustario64-viewer view ROM --mario --record private/runs`) from BOB's script
start in the native decomp and compares every tick; a path the port does not
support ends the comparison at the previous tick, as it ends play. The CI test
`played_sessions_replay_exactly_in_the_decomp` does the same for
`play::Session` runs on the authored playground.

The authored tests run on independently authored collision streams, terrain,
tables and animation data (CI-safe); the ignored tests use BOB's real
collision, the real trig tables and Mario's real animations from the owner's
ROM. Coverage counts are in [docs/FIDELITY.md](../docs/FIDELITY.md).

## Camera component oracle

`c/camera_unit.c` compiles `c/excerpts/camera.c` with original headers and
authored prototypes for helpers absent from camera.h (`c/shim/camera_boundary.h`).
`src/camera.rs` holds the existing global lock, loads authored/owner terrain and
trig tables, and reports exact native words. It runs the persistent Lakitu and
transition stage independently of mode dispatch; the complete Mario tick oracle
is unchanged.

`cargo test --locked -p rustario64-oracle --test camera` runs the authored
component and radial-goal cases; repeat with `--release`. The ignored
`bob_camera_components_match_with_rom_tables` case requires `RUSTARIO64_ROM`.
The crashing NULL-contact/pole paths are rejected before invoking native C.
See docs/FIDELITY.md for scope and missing complete-camera comparisons.

`--test lakitu` compares every modeled field after `update_lakitu`, including
transition state, speeds, deterministic shakes, render position/focus, and
collision flags. The adapter copies authored goals and Mario positions into C,
never the Rust result after a tick. `lakitu_end_frame` performs the outer
`update_camera` assignment of lastFrameAction separately. The 94-word layout is
generated on both sides from field mappings only; `tools/lakitu_layout.py
--check` verifies it and native reset checks the word count.

`set_camera_shake_from_hit` is renamed during camera excerpt preprocessing to
keep Mario's existing event-recording boundary unchanged. The native camera
calls the original deterministic hit/shake functions. `random_float` maps to an
aborting boundary; active handheld or shock requests are excluded before that
path. Full handheld/spline/random-vector functions are retained verbatim for
the native call graph, but RNG-driven behavior is not ported or claimed. No
reference asset data or spline control points are copied into the repository.
